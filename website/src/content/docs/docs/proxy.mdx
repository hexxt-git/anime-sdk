Most streaming servers block cross-origin requests and require custom `Referer` or `User-Agent` headers. Browsers can't set these freely, so direct playback from a web app fails. The built-in proxy solves this by fetching video data server-side and forwarding it to the browser with full CORS headers.

## Enabling the proxy

Pass `proxy` config to `createSdk()`:

```ts
import { startServerV2, createSdk } from 'anime-sdk';

startServerV2({
  sdk: createSdk({
    proxy: {
      signSecret: process.env.PROXY_SECRET, // HMAC-sign URLs (recommended in prod)
      allowedHosts: ['cdn.example.com'], // SSRF allowlist (optional)
    },
  }),
  port: 3030,
});
```

Or via CLI — proxy is on by default:

```sh
PROXY_SIGN_SECRET=$(openssl rand -hex 32) npx anime-sdk
```

Three things happen automatically:

1. A `/proxy` endpoint becomes active.
2. Every `stream.url` in `/episode/:id/stream` responses is rewritten to go through `/proxy`, with the required headers encoded in the URL. Your frontend uses `stream.url` as-is.
3. `stream.origin.host` still tells you the real CDN hostname even when proxied.

## How stream URLs are rewritten

**Without proxy:**

```json
{
  "url": "https://cdn.example.com/ep1.m3u8",
  "origin": {
    "host": "cdn.example.com",
    "url": "https://cdn.example.com/ep1.m3u8",
    "proxied": false
  },
  "headers": { "Referer": "https://provider.com/watch/ep-1" }
}
```

**With proxy:**

```json
{
  "url": "http://localhost:3030/proxy?url=https%3A%2F%2Fcdn.example.com%2Fep1.m3u8&h=eyJS...&sig=abc",
  "origin": {
    "host": "cdn.example.com",
    "url": "https://cdn.example.com/ep1.m3u8",
    "proxied": true
  },
  "headers": {}
}
```

The `h` param is the base64-encoded JSON of the required upstream headers. The `sig` param is the HMAC-SHA256 signature (when `signSecret` is configured). Your frontend uses `stream.url` as-is — no header forwarding needed.

## HMAC-signed URLs

Setting `signSecret` in the proxy config makes `/proxy` require a valid `sig` HMAC-SHA256 query parameter. The server signs URLs it emits automatically. Unsigned or invalid-signature requests return **401**.

Manual signing (for custom clients):

```ts
import * as crypto from 'node:crypto';
const sig = crypto.createHmac('sha256', secret).update(targetUrl).digest('hex');
const url = `${proxyBase}?url=${encodeURIComponent(targetUrl)}&sig=${sig}`;
```

## SSRF allowlist

`allowedHosts: string[]` restricts `/proxy` to a suffix-matched list of upstream hostnames. Each entry covers all subdomains:

```ts
createSdk({
  proxy: {
    allowedHosts: ['wixstatic.com', 'allanime.day', 'mp4upload.com', 'uploads.mangadex.org'],
  },
});
```

Targets outside the list return **403**. When unset, all hosts are allowed — fine for local development.

## HLS manifest rewriting

When the upstream response is an HLS manifest, the proxy rewrites every URI in it — segment URLs, sub-playlist URLs, `#EXT-X-KEY` encryption key URLs, `#EXT-X-MAP` init URIs — to also go through `/proxy`. The header chain propagates automatically.

This means an HLS player (e.g. [hls.js](https://github.com/video-dev/hls.js)) only needs to load the proxy URL for the master playlist. All subsequent requests are handled transparently.

## Playing streams in the browser

With proxy enabled, `stream.url` is a plain URL the browser can fetch:

```tsx
import Hls from 'hls.js';

function Player({ stream }: { stream: Stream }) {
  const ref = useRef<HTMLVideoElement>(null);

  useEffect(() => {
    const v = ref.current!;
    if (stream.isHls && Hls.isSupported()) {
      const hls = new Hls();
      hls.loadSource(stream.url); // proxy URL: just works
      hls.attachMedia(v);
      return () => hls.destroy();
    }
    v.src = stream.url;
  }, [stream.url, stream.isHls]);

  return (
    <video ref={ref} controls crossOrigin="anonymous">
      {stream.subtitles.map((s, i) => (
        <track key={i} kind="subtitles" src={s.url} srcLang={s.language} label={s.label} />
      ))}
    </video>
  );
}
```

No `xhrSetup`, no custom headers, no CORS workarounds.

## `/proxy` endpoint

```
GET /proxy?url=<encoded-url>[&h=<base64-headers>][&ct=<content-type>][&sig=<hmac-sha256>]
```

| Param | Required                 | Description                                                |
| ----- | ------------------------ | ---------------------------------------------------------- |
| `url` | ✓                        | URL-encoded target URL to fetch                            |
| `h`   |                          | Base64-encoded JSON of request headers to forward upstream |
| `ct`  |                          | Override the response `Content-Type`                       |
| `sig` | when `signSecret` is set | HMAC-SHA256 of `url` plus optional `\|h=<h>`, hex-encoded  |

The response includes `Access-Control-Allow-Origin: *`.

## Subtitle proxying

Subtitle `url` fields in `Stream.subtitles` are also rewritten through `/proxy` with a `ct=text/vtt` hint. Pass the rewritten URL straight to a `<track>` element — no `crossOrigin` issues:

```tsx
<video crossOrigin="anonymous" controls>
  {stream.subtitles.map((t) => (
    <track key={t.url} kind="subtitles" src={t.url} srcLang={t.language} label={t.label} />
  ))}
</video>
```

<Aside type="caution">
  The proxy will forward any URL with any headers to the upstream server. Do not expose it to the
  public internet without configuring `signSecret` and `allowedHosts`.
</Aside>
